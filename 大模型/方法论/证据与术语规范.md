# 大模型档案证据与术语规范

> [!info] 知识导航
> 上级档案库：[[大模型/README|开放权重大模型档案库]]  
> 相关概念：[[开放权重模型]] · [[预训练与后训练]] · [[稠密模型与稀疏专家模型]] · [[长上下文]] · [[模型量化与部署]]

## 一、证据规则

### A：官方披露

开发机构直接公开，并且能够明确对应到目标模型和版本。

可接受来源：

- 官方技术报告或论文；
- 官方模型卡；
- 官方 GitHub 仓库；
- 官方 Hugging Face、ModelScope 等模型组织；
- 官方配置文件和权重元数据；
- 官方发布公告与技术博客；
- 官方许可证文件。

记录格式示例：

```text
[A｜官方模型卡｜2026-08-20｜对应 Model-X-Instruct]
```

注意：官方披露不等于完整披露。家族级描述不能自动套用到每个变体，API 产品的信息也不能自动套用给公开权重。

### B：论文推断

独立论文或可重复分析得出的判断，但开发机构没有直接确认。

必须使用以下表达：

- “研究者推断”；
- “结果与某方法一致”；
- “可能采用”；
- “尚无官方确认”。

不能把推断改写成官方事实。

### C：社区复现

社区通过公开权重、配置、代码和可重复实验得到的结果。

应记录：

- 仓库和 commit；
- 推理框架及版本；
- 硬件；
- 精度；
- 输入和输出长度；
- 并发量；
- 命令和结果。

社区复现只能证明该公开制品在特定环境中的行为，不能证明开发机构内部使用了某种训练方法。

### U：未知

截至档案修订日期没有可靠证据，或来源冲突无法消解。

统一写法：

```text
[U｜未知｜截至 YYYY-MM-DD 未发现可核验公开披露]
```

“未知”是重要事实，不应用猜测补空白。

## 二、证据冲突处理

通常采用以下优先级：

```text
同版本机器可读官方配置
> 同版本官方技术报告或模型卡
> 官方家族级描述
> 独立论文推断
> 可复现社区实验
> 无法复现的社区说法
```

但配置文件只能证明公开制品的结构，不能单独证明训练数据和训练过程。

如果官方宣称 128K 上下文，而社区只在 64K 稳定复现，应分别记录，不能平均成 96K，也不能直接删除官方数据。

## 三、模型对象的区别

### 模型家族

共享核心架构和训练路线的一组模型，例如 Qwen3。

### 基础模型

经过预训练或继续预训练的权重，通常标为 Base、Pretrained。

### 后训练模型

经过 SFT、偏好优化或强化学习的权重，例如 Instruct、Chat、Reasoning。

### 部署制品

量化、裁剪、格式转换或推理框架中的具体文件，例如 AWQ、GPTQ、GGUF。

这四类对象不能混写。

## 四、核心架构术语

### Dense

稠密模型。每个 token 基本都会经过同一套主要参数。

### Sparse MoE

稀疏专家模型。模型有许多专家，每个 token 只选择少数专家参与计算。

记录 MoE 时必须分开写：

- 总参数量；
- 每 token 激活参数量；
- 专家数量；
- 每 token 激活专家数；
- 共享专家；
- 路由方式。

### MHA、GQA、MQA

- **MHA**：每个 Query 头拥有自己的 Key/Value 头；
- **GQA**：若干 Query 头共享一组 Key/Value；
- **MQA**：所有 Query 头共享一组 Key/Value。

减少 KV 头主要降低生成时 KV cache 的显存和带宽需求。

### RoPE

通过旋转 Query 和 Key，把位置信息放入注意力计算。

### YaRN

一种 RoPE 长上下文扩展方法，通过调整不同频率的缩放，让模型更好适应比原训练长度更长的输入。

只修改配置中的最大长度，不等于模型经过了可靠的长上下文训练。

## 五、训练阶段术语

### 预训练

模型在大量数据上学习预测 token 或恢复被遮挡内容的阶段。

### Continued Pretraining

从已有基础模型继续做语言模型预训练，用于增加领域、语言、知识或长上下文能力。它不同于指令微调。

### 课程学习

按难度、长度、领域或质量有意安排训练顺序。存在多个训练阶段不自动等于课程学习。

### SFT

监督微调。使用输入与理想输出示范，让模型学习指令、对话和任务格式。

### RLHF

使用人类偏好形成奖励信号，再通过强化学习优化模型。

### RLAIF

使用 AI 评审产生偏好或奖励。人仍可能设计原则、样本和验收规则。

### DPO

直接使用偏好回答与非偏好回答训练模型，通常不需要单独运行 PPO。

### ORPO

把普通 SFT 和偏好约束合并在一个训练阶段中，通常不需要独立参考模型。

### GRPO

同一问题生成一组候选，根据组内相对奖励更新模型，通常不需要独立 critic 模型。

### 可验证奖励

由程序、测试、规则或环境客观检查的奖励，例如数学答案、代码测试、SQL 执行或定理检查。

### 蒸馏

让学生模型模仿教师模型。必须区分：

- 概率分布蒸馏；
- 最终回答蒸馏；
- 推理轨迹蒸馏；
- 偏好蒸馏；
- 中间表示蒸馏。

使用合成数据不一定就是蒸馏。

## 六、数据术语

### 训练 token 数

模型训练实际看到的 token 总量。它不等于原始抓取数据大小。

### 数据配比

网页、代码、数学、书籍、论文、语言等在实际训练采样中的比例。

### 去重

需要区分：

- 文档精确去重；
- 文档近似去重；
- 段落或句子去重；
- Benchmark 去污染。

### 合成数据

由模型、程序、模拟器或规则生成的数据。应记录生成者、生成量、保留量、验证方法和占比。

## 七、上下文长度的四种口径

档案必须分别记录：

1. 配置文件最大长度；
2. 官方宣称长度；
3. 实际训练长度；
4. 社区稳定复现长度。

“能够输入 1M token”不等于“能够可靠利用 1M token”。

## 八、量化与部署

### 量化

用更少位数保存权重、激活或 KV cache。

必须记录：

- 官方或第三方；
- 来源 checkpoint；
- 方法；
- 权重、激活和 KV cache 位宽；
- group size；
- 校准数据；
- 精度变化。

### 推理部署

模型架构相同，使用不同引擎、硬件、精度、并发和输入输出长度时，性能可能差异很大。

任何速度数字都必须同时记录：

- 硬件；
- GPU 数量；
- 推理引擎及版本；
- 权重和激活精度；
- 输入长度；
- 输出长度；
- 并发；
- TTFT、单 token 延迟或吞吐量。

## 九、最低完整度要求

每篇档案至少回答：

1. 精确模型系列和版本是什么；
2. 有哪些官方开放权重；
3. 许可证是什么；
4. Dense 还是 MoE；
5. 总参数与激活参数；
6. 注意力和位置编码；
7. 训练长度与宣称长度；
8. 预训练目标与 token 数；
9. 数据来源、清洗、去重和配比披露程度；
10. 是否使用合成数据和蒸馏；
11. 是否经过 SFT；
12. 使用何种偏好优化或 RL；
13. 是否使用可验证奖励；
14. 推理、工具调用和多模态方法；
15. 官方量化与部署方式；
16. 能力、评测和局限；
17. 哪些字段明确未知；
18. 每项结论的证据等级和来源。

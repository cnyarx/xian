# 部署一个本地模型

## 目标

选择许可证允许、硬件可承载的官方开放权重模型，在本机启动只监听回环地址的 HTTP 服务，并完成：

```text
核验模型 → 固定工具版本和模型标识 → 启动服务
→ 健康检查 → API 请求 → 流式/非流式结果检查
→ 断网测试 → 端口与日志安全检查
```

本项目提供 `llama.cpp` 和 Ollama 两条路线。选择一条完成即可。命令和模型目录会变化，执行前必须对照当时的官方文档。

## 环境与硬件边界

- 命令行客户端只使用 Python 标准库，需要 Python 3.10+；
- 可选 Gradio 界面需要 Python 3.10+。安装时固定实际版本，例如 `python -m pip install "gradio>=5,<7"`，并保存 `pip freeze`；Gradio 官方未提供覆盖所有版本组合的兼容矩阵，若 API 不匹配应按安装版本文档调整；
- llama.cpp 与 Ollama 的 CPU/GPU 支持和安装方式随版本变化，必须记录工具版本或 commit；
- 0.8B 级 4-bit 权重文件本体通常低于 1 GiB，但运行还需要 KV Cache、临时缓冲和程序开销；建议至少预留数 GiB 可用内存。更大模型应按“权重字节数 + KV Cache + 运行时余量”估算，不能只看参数量；
- GPU 不是必需条件，CPU 可运行小模型但速度依硬件而异。本项目不承诺固定 token/s。

当前写作环境没有安装模型服务和权重，因此下面只提供经过静态检查的复现流程；真实验收必须在目标机器完成。

## 安全边界

- 默认只绑定 `127.0.0.1`，不要无认证暴露到 `0.0.0.0` 或公网；
- 模型权重只从发布者官方页面或可信镜像获取；
- 记录许可证、模型 ID、revision/digest、量化格式和文件哈希；
- API 返回是模型生成内容，不自动等于事实；
- 下载模型需要联网，完成本地缓存后才能做断网运行测试。

## 路线 A：llama.cpp

### 1. 安装并固定版本

使用官方 Releases、构建文档或包管理方式：https://github.com/ggml-org/llama.cpp

记录版本：

```bash
llama-server --version
```

若从源码构建，记录 commit SHA 和构建参数。官方顶层 README 当前给出的快速示例是：

```bash
llama serve -hf ggml-org/Qwen3.5-0.8B-GGUF
```

该名称只是官方文档当前示例，不是永久默认模型。首次运行会联网获取权重；执行前仍需打开对应模型卡，核验上游发布者、量化者、许可证和文件。

不同安装方式的可执行文件可能叫 `llama-server` 或由 `llama` 子命令启动，应以实际版本的 `--help` 和 server 文档为准。

### 2. 明确绑定地址

不要依赖默认值。根据已安装版本的帮助信息显式设置 host 和 port。例如常见独立服务命令形式为：

```bash
llama-server \
  -hf ggml-org/Qwen3.5-0.8B-GGUF \
  --host 127.0.0.1 \
  --port 8080
```

参数在版本间可能变化；若 `--help` 不支持，应停止并查对应版本文档，不要猜参数。

### 3. 请求 OpenAI 兼容接口

官方 server 文档将服务描述为 OpenAI-compatible，但不表示覆盖 OpenAI 的全部 API。先按对应版本文档确认 `/v1/chat/completions`：

```bash
curl --fail --silent --show-error \
  http://127.0.0.1:8080/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "messages": [
      {"role": "user", "content": "用一句话解释什么是向量。"}
    ],
    "temperature": 0,
    "max_tokens": 64
  }'
```

若目标模型需要特定聊天模板，应使用模型卡和当前 server 支持的模板；不能把任意 Base 模型当聊天模型。

### 4. 固定本地文件

比浮动 `-hf` 更严格的复现实验应保存：

- 实际 GGUF 文件名和 SHA-256；
- 下载仓库和 revision；
- llama.cpp commit/version；
- 启动参数；
- CPU/GPU、内存和 offload 设置。

之后可用对应版本支持的本地模型参数启动，避免每次解析浮动远程仓库。

## 路线 B：Ollama

### 1. 安装与版本

按官方页面安装：https://ollama.com/download

记录：

```bash
ollama --version
```

当前 Quickstart 使用：

```bash
ollama run gemma4
```

模型名称和标签可能变化，且带 `:cloud` 的模型不是完全本地运行。要满足本项目目标，必须选择已下载到本机、许可证已核验且断网可运行的本地模型标签。

### 2. 核验本地模型

先列出已经下载到本机的模型，再把精确名称保存为环境变量：

```bash
ollama list
export OLLAMA_MODEL="在上一步列表中核验过的精确模型名和标签"
ollama show "$OLLAMA_MODEL"
```

`OLLAMA_MODEL` 不能留空，也不能凭教程猜测。把 `ollama show` 返回的模型名、参数、量化、许可证来源和 digest 复制到实验记录。

### 3. 调用本地 Generate API

Ollama 当前 API introduction 给出的基础地址是：

```text
http://localhost:11434/api
```

非流式调用：

```bash
curl --fail --silent --show-error \
  http://127.0.0.1:11434/api/generate \
  -H 'Content-Type: application/json' \
  -d "{
    \"model\": \"$OLLAMA_MODEL\",
    \"prompt\": \"用一句话解释什么是向量。\",
    \"stream\": false
  }"
```

`stream` 和返回字段应以实际安装版本的 API 文档及实测响应为准。

## 通用 Python 客户端

保存为 `local_chat_client.py`。它不启动服务，只调用你已经验证的本地端点：

```python
import argparse
import json
from urllib import request


def post_json(url, payload, timeout=120):
    body = json.dumps(payload, ensure_ascii=False).encode("utf-8")
    req = request.Request(
        url,
        data=body,
        headers={"Content-Type": "application/json"},
        method="POST",
    )
    with request.urlopen(req, timeout=timeout) as response:
        if response.status != 200:
            raise RuntimeError(f"HTTP {response.status}")
        return json.loads(response.read().decode("utf-8"))


def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("prompt")
    parser.add_argument("--backend", choices=["ollama", "llamacpp"], required=True)
    parser.add_argument("--model")
    parser.add_argument("--host", default="127.0.0.1")
    parser.add_argument("--port", type=int)
    args = parser.parse_args()

    if args.host not in {"127.0.0.1", "localhost", "::1"}:
        raise SystemExit("refusing non-loopback host")

    if args.backend == "ollama":
        if not args.model:
            raise SystemExit("--model is required for Ollama")
        port = args.port or 11434
        result = post_json(
            f"http://{args.host}:{port}/api/generate",
            {"model": args.model, "prompt": args.prompt, "stream": False},
        )
        if "response" not in result:
            raise RuntimeError(f"unexpected Ollama response keys: {sorted(result)}")
        print(result["response"])
    else:
        port = args.port or 8080
        result = post_json(
            f"http://{args.host}:{port}/v1/chat/completions",
            {
                "messages": [{"role": "user", "content": args.prompt}],
                "temperature": 0,
                "max_tokens": 128,
            },
        )
        try:
            print(result["choices"][0]["message"]["content"])
        except (KeyError, IndexError, TypeError) as error:
            raise RuntimeError(f"unexpected llama.cpp response: {result}") from error


if __name__ == "__main__":
    main()
```

运行示例：

```bash
python local_chat_client.py \
  --backend ollama \
  --model "$OLLAMA_MODEL" \
  "用一句话解释什么是向量。"
```

或：

```bash
python local_chat_client.py \
  --backend llamacpp \
  "用一句话解释什么是向量。"
```

客户端拒绝非回环 host，避免误把教程示例直接用于远程服务。

## Gradio 本地界面

Gradio 只是本地服务的界面层，不负责下载或运行模型。先确认 Ollama 或 llama.cpp API 已按前文启动，再安装并记录 Gradio 版本：

```bash
python -m pip install "gradio>=5,<7"
python -c "import gradio; print(gradio.__version__)"
python -m pip freeze > local-deploy-requirements.txt
```

保存为 `local_chat_ui.py`，并与 `local_chat_client.py` 放在同一目录：

```python
import argparse

import gradio as gr

from local_chat_client import post_json


def parse_args():
    parser = argparse.ArgumentParser()
    parser.add_argument("--backend", choices=["ollama", "llamacpp"], required=True)
    parser.add_argument("--model")
    parser.add_argument("--host", default="127.0.0.1")
    parser.add_argument("--api-port", type=int)
    parser.add_argument("--ui-port", type=int, default=7860)
    args = parser.parse_args()
    if args.host not in {"127.0.0.1", "localhost", "::1"}:
        raise SystemExit("refusing non-loopback host")
    if args.backend == "ollama" and not args.model:
        raise SystemExit("--model is required for Ollama")
    return args


def build_generate(args):
    def generate(prompt):
        prompt = prompt.strip()
        if not prompt:
            return "请输入问题。"

        if args.backend == "ollama":
            port = args.api_port or 11434
            result = post_json(
                f"http://{args.host}:{port}/api/generate",
                {"model": args.model, "prompt": prompt, "stream": False},
            )
            if "response" not in result:
                raise RuntimeError(
                    f"unexpected Ollama response keys: {sorted(result)}"
                )
            return result["response"]

        port = args.api_port or 8080
        result = post_json(
            f"http://{args.host}:{port}/v1/chat/completions",
            {
                "messages": [{"role": "user", "content": prompt}],
                "temperature": 0,
                "max_tokens": 128,
            },
        )
        try:
            return result["choices"][0]["message"]["content"]
        except (KeyError, IndexError, TypeError) as error:
            raise RuntimeError(f"unexpected llama.cpp response: {result}") from error

    return generate


def main():
    args = parse_args()
    generate = build_generate(args)

    with gr.Blocks() as demo:
        gr.Markdown("# 本地模型问答")
        prompt = gr.Textbox(label="问题", lines=4)
        answer = gr.Textbox(label="模型回答", lines=10)
        submit = gr.Button("发送")
        submit.click(fn=generate, inputs=prompt, outputs=answer)

    demo.launch(
        server_name="127.0.0.1",
        server_port=args.ui_port,
        share=False,
        show_error=False,
    )


if __name__ == "__main__":
    main()
```

Ollama 运行示例：

```bash
python local_chat_ui.py \
  --backend ollama \
  --model "$OLLAMA_MODEL"
```

llama.cpp 运行示例：

```bash
python local_chat_ui.py --backend llamacpp
```

浏览器只访问 `http://127.0.0.1:7860`。不要设置 `share=True`，也不要把 `server_name` 改为 `0.0.0.0`，除非已经补充认证、网络隔离和数据安全设计。

界面验收至少包括：空输入显示明确提示；正常问题返回非空回答；API 服务停止时界面报告失败而不是伪造回答；`ss -ltn` 显示 UI 和模型 API 都只监听回环地址。

## 端口检查

Linux 可检查监听地址：

```bash
ss -ltn
```

找到目标端口后，必须显示 `127.0.0.1:<port>` 或 `[::1]:<port>`，而不是 `0.0.0.0:<port>` 或 `[::]:<port>`。

## 断网验收

先在联网状态完成合法下载，然后：

1. 停止外部网络访问或使用隔离环境；
2. 重新启动服务，不允许重新下载；
3. 调用同一 API；
4. 确认服务没有访问云端模型；
5. 记录实际日志。

`ollama run ...:cloud` 或远程推理端点不满足“本地模型断网运行”。

## 性能记录

至少记录：

| 字段 | 结果 |
|---|---|
| 工具与版本/commit |  |
| 模型 ID、revision/digest |  |
| 权重许可证来源 |  |
| GGUF/量化格式与 SHA-256 |  |
| CPU/GPU、内存 |  |

| TTFT |  |

不同工具对 token 计数和计时字段定义可能不同，比较前必须统一口径。

## 功能验收

- 正常短问题能返回非空文本；
- 空输入得到明确处理，不导致服务崩溃；
- 长输入超过限制时返回可解释错误；
- 客户端超时能退出；
- 端口只绑定本地；
- 断网后仍可使用已缓存权重；
- 模型输出中的事实经过独立核验；
- 日志不包含密钥和不必要的敏感输入。

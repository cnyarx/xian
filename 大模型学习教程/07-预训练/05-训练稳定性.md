# 训练稳定性

## 为什么大模型训练会不稳定

训练涉及数十亿参数、海量数据、低精度数值和大量设备。一次异常可能使损失突然上升、出现 NaN 或让模型无法恢复。

## 梯度问题

- 梯度消失：越往前层梯度越小，参数几乎不更新。
- 梯度爆炸：梯度巨大，单步把参数推离正常区域。
- 梯度裁剪：当整体梯度范数超过阈值时按比例缩小。

$$g\leftarrow g\cdot\min\left(1,\frac{c}{\|g\|}\right)$$

$c$ 是阈值。

## 数值精度

FP32 精确但显存和计算成本高。BF16/FP16 用较少位表示数，速度更快但范围或精度较低。混合精度让部分计算低精度、关键累积和参数副本保持更高精度。

FP16 常需损失缩放防止小梯度下溢；BF16 指数范围与 FP32 相同，通常更不易溢出，但精度位更少。

## 损失尖峰

Loss Spike 是损失突然异常升高。可能原因包括异常数据批次、学习率过大、数值溢出、优化器状态异常或分布式通信错误。不能仅看曲线猜原因，应检查真实批次、梯度、日志和硬件状态。

### 一次排查示例

假设正常训练 loss 在 2.1 左右，第 12000 步突然变成 18，随后出现 `NaN`。可以按证据链排查：

1. 保存并重放第 12000 步的样本，检查是否有超长、乱码或异常重复文本；
2. 检查该步学习率是否因调度器恢复错误从 $2\times10^{-4}$ 跳到 $2\times10^{-2}$；
3. 记录裁剪前梯度范数，例如从正常约 1.5 突增到 800；
4. 检查 FP16 loss scale 是否连续下调，以及参数、梯度中首次出现 `Inf/NaN` 的层；
5. 用最近检查点在同一批次重跑。若可重复，优先调查数据或确定性数值路径；若不可重复，再调查硬件、通信或并发状态。

这些数值只是排查示例，不是所有模型的正常阈值。关键是保留批次、配置、检查点和日志，使异常能被重放。

## 稳定训练措施

- 合理初始化、Pre-Norm/RMSNorm、残差连接。
- 学习率 warmup 和衰减。
- 梯度裁剪。
- 数据质量检查。
- NaN/Inf 监控。
- 定期保存模型、优化器、随机数状态。
- 在检查点上做恢复演练。

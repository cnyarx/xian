# 09-推理与生成答案

## [[../09-推理与生成/01-推理概览|01-推理概览]]

1. 训练计算损失和梯度并更新参数；推理固定参数，只计算输出。
2. prefill 并行处理已有提示并建立 KV cache；decode 每轮生成新 token，并把其 K/V 追加到缓存。
3. 合并更多请求通常提高设备利用率和吞吐，但单个请求可能排队更久、每步批次更大，延迟上升。
4. 生成 EOS、达到最大 token 数、命中停止字符串；还可有超时或安全策略停止。

## [[../09-推理与生成/02-采样策略|02-采样策略]]

1. 温度增大时 logits 差距被缩小，分布通常更平、更随机；温度降低则更尖。
2. Top-k 固定保留概率最高的 k 项；Top-p 保留累计概率达到阈值的最小候选集合，集合大小随分布变化。
3. 当前最优 token 可能进入后续概率很低的路径；另一开始略低的 token 可能使整句联合概率更高。
4. 创作常用适度温度和 Top-p 保留多样性；代码生成通常偏低温度并配合测试验证。没有通用参数，应在任务数据上评测正确率、重复和多样性。

## [[../09-推理与生成/03-KV Cache|03-KV Cache]]

1. 原题没有给模型数值。单序列粗估：$2LTH_{kv}d_{head}\times$ 每元素字节；若有批量再乘序列数，并计实现开销。
2. 其他量不变时，缓存与 $T$ 线性增长，上下文翻倍，缓存约翻倍。
3. GQA 让多个 Query 头共享较少 KV 头，公式中的 $H_{kv}$ 下降。
4. PagedAttention 把不等长请求的 KV cache 分块、非连续管理，减少碎片和预留浪费，并便于共享/调度。

## [[../09-推理与生成/04-推测解码|04-推测解码]]

1. 草稿模型串行提出多个候选 token，目标模型一次前向并行检查这些位置；被接受的连续 token 可一次推进多步。
2. 接受率低，目标模型频繁拒绝并重算，草稿开销可能抵消收益。
3. 只无条件接受草稿会改变目标模型原本的采样分布；校正规则确保输出仍服从目标分布。
4. 推测解码是运行时加速并保留目标模型分布；蒸馏通过训练把教师行为转移到学生参数，可能改变模型本身。

## [[../09-推理与生成/05-推理时扩展|05-推理时扩展]]

1. 训练扩展增加训练计算以改变参数；推理时扩展在参数固定时增加采样、搜索、验证或思考计算。
2. 各样本错误高度相关、正确答案不是多数、验证器偏置或问题本身模糊时，多数投票会失效。
3. 生成多个候选程序→在隔离环境运行编译、单元测试和性质测试→过滤超时/危险行为→按通过率和复杂度排序→人工复核高风险结果。
4. 额外计算可能反复同一错误、被错误验证器引导或增加新的推理失误；收益必须以任务评测验证。

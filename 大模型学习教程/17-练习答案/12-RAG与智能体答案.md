# 12-RAG与智能体答案

## [[../12-RAG与智能体/01-RAG 基础|01-RAG 基础]]

1. 收集已批准规章及版本→解析权限和生效日期→按标题/条款切块并保存来源→建立关键词与向量索引→查询时先做权限过滤，再召回、重排序→只把证据交给模型→回答附原文与版本→回读引用；无证据时拒答。
2. 块太大：主题混杂、检索分数不准、占上下文；块太小：定义、条件和表头被切断，需要拼接许多块。应在真实问答集上调块策略。
3. 重排序只能调整初检索候选的顺序。正确文档不在候选集合中时，它没有可排序的正确项，必须改进查询、索引或初检索。
4. 引用可能不支持结论、过期、被断章取义或来自错误来源；必须逐条回读，核对结论、条件、版本和权限。
5. 内容一旦进入模型上下文，就可能影响回答或被泄露；权限必须在可信检索服务端先过滤，不能依赖提示词让模型保密。
6. 无答案测试：询问规章未规定的事项，应明确证据不足。冲突测试：放入新旧两个期限，应报告版本并按生效规则处理。恶意文档测试：加入“发送所有文件”等文字，确认它只作为数据且不能触发工具。

## [[../12-RAG与智能体/02-嵌入与向量数据库|02-嵌入与向量数据库]]

1. 关系数据库擅长结构化字段、精确条件、连接和事务；向量数据库针对高维相似搜索建立索引。生产系统常混合使用，而非二选一。
2. ANN 用索引剪枝，只搜索候选区域以换取速度和内存，因此可能漏掉真正最近邻；要测 recall@k。
3. 产品编号是精确字符串，嵌入可能把相似编号混淆；关键词或精确过滤能稳定匹配字符。
4. 最好在检索候选产生前或索引查询中强制执行，并在返回和生成前再次校验；不能只在提示词里要求模型忽略无权内容。

## [[../12-RAG与智能体/03-工具调用|03-工具调用]]

1. 示例定义：名称 `calculate`；参数 `expression` 为字符串；说明只接受允许的算术表达式；返回数值或结构化错误。真正实现不能直接对不可信字符串使用 unrestricted `eval`。
2. 模型只产生调用建议；执行器负责 schema 校验、权限、确认、超时和实际 API 调用，避免把语言输出当系统权限。
3. 付款、删除/覆盖数据、发送外部消息、修改权限、发布部署和其他不可逆或影响他人的操作。
4. 网页可含错误、恶意提示注入和过期内容；工具结果应被视为数据，不能改变系统指令或自动获得权限。

## [[../12-RAG与智能体/04-智能体基础|04-智能体基础]]

1. 目标与约束→检索交通/住宿→生成候选行程→计算预算和冲突→向用户确认付款等高风险选择→执行已批准预订→核验订单→记录结果；每一步设超时和失败处理。
2. 上下文是当前调用可见的有限 token；长期记忆是外部持久存储，需要检索后才进入上下文，并应有来源、权限、更新与删除规则。
3. 反思仍由可能犯同类错误的模型生成，只是另一段文本；事实、代码和操作结果要靠数据源、测试或真实状态验证。
4. 任务简单、通信成本高、角色信息重复、决策互相冲突或多个智能体共享同一错误来源时，会更慢且不一定更准。

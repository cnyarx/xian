# 10-训练系统与规模化答案

## [[../10-训练系统与规模化/01-训练系统概览|01-训练系统概览]]

1. 训练除参数外还需梯度、优化器状态、激活、中间缓冲、通信缓冲和运行时开销；低精度参数也可能配高精度主副本。
2. 参数、梯度、优化器状态、前向激活、临时/通信缓冲；还应预留框架碎片和内核工作区。
3. 数据并行拆样本；张量并行拆一层内的矩阵或张量运算；流水线并行拆不同层/阶段。
4. 所有需要跨设备通信的方案都会受影响；张量并行每层频繁通信尤其依赖低延迟高带宽，数据并行的梯度同步也可能成为瓶颈。

## [[../10-训练系统与规模化/02-数据并行|02-数据并行]]

1. $8\times16\times4=512$ 个样本；前提是每设备每个微批确为 8 且没有特殊丢弃。变长文本还应记录有效 token 数。
2. 两个副本会分别变成 $w-\eta g_0$ 与 $w-\eta g_1$，参数从此分叉；同步共同梯度后，各卡才能保持同一模型。
3. 若一张卡只有 20 个有效 token，另一张有 100 个，两个“卡内平均梯度”各占一半会高估前者。应按有效 token 数加权，并核对损失与通信的归约方式。
4. ZeRO-3 分片优化器状态、梯度和参数；计算某层时仍可能需要 All-Gather 当层参数，反向时还需 Reduce-Scatter 梯度，因此节省显存不等于消除通信。
5. 检查每卡样本 ID、全局样本/token 数、数据加载等待、通信占比、bucket 时间线、最慢卡等待、互联带宽，以及增加设备后的实际吞吐而非只看单步成功。

## [[../10-训练系统与规模化/03-模型并行|03-模型并行]]

1. 张量并行拆同一层的矩阵维度；流水线并行把连续层放在不同阶段。
2. 一层运算中经常要 AllReduce 或 AllGather，通信位于关键路径且频率高。
3. 某些流水线阶段因依赖前后阶段而空闲的时间/设备槽位，常出现在批次开始和结束。
4. 专家参数分布在不同设备，token 按路由发送给对应专家并取回结果，这就是专家并行的核心通信。

## [[../10-训练系统与规模化/04-混合精度训练|04-混合精度训练]]

1. 每元素字节少，参数、激活和通信数据更小；支持低精度矩阵单元的硬件通常吞吐也更高。
2. 很小的梯度在 FP16 中可能下溢为 0；先放大损失和梯度，更新前再缩回，可保留更多有效值。
3. BF16 指数范围大、较少溢出，但尾数精度低；是否更快或可用取决于硬件。
4. 累加、归一化、主权重或某些敏感算子需要更大范围/精度，以避免误差累积和训练不稳定。

## [[../10-训练系统与规模化/05-检查点与容错|05-检查点与容错]]

1. Adam 等优化器下一步依赖历史一阶、二阶矩；丢失后即使参数相同，后续更新也不同。
2. 防止进程中途失败留下“名称正常但内容只写了一半”的检查点；先完整写临时文件，再原子替换正式名称。
3. 不足。还要校验大小/哈希、元数据、分片完整性，并实际加载后做至少一次前向或恢复训练测试。
4. 状态分散在多进程/设备，需一致的全局步数和分片映射；设备数或并行拓扑变化时还可能重分片。

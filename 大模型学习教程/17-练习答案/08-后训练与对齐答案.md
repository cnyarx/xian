# 08-后训练与对齐答案

## [[../08-后训练与对齐/01-后训练概览|01-后训练概览]]

1. 基础模型优化的是文本续写，不是稳定遵守用户意图、安全边界和回答格式。
2. 示例：人工示范答案、成对偏好、标量或可验证奖励、教师模型生成的合成数据。
3. 可能改善已有知识的调用和表达，也可能通过继续训练加入部分新信息；但小规模后训练不能可靠补齐基础模型从未学过的大量知识，还可能遗忘。应以独立测试判断。
4. 教师生成一个看似正确但计算错误的解题步骤；若未验证就大量复制，学生会同时学习错误结论和错误推理模式。

## [[../08-后训练与对齐/02-监督微调|02-监督微调]]

1. `{"instruction":"把句子改得更礼貌：马上回复","response":"方便时请尽快回复，谢谢。"}`。
2. 目标通常是学习助手回答，而不是让模型复述用户提示；屏蔽提示损失还避免长提示淹没回答 token。某些训练设计也会计算全序列损失，需明确口径。
3. 单一领域或句式会让模型只学窄模式；任务、长度、语气和边界案例多样性有助于泛化。
4. 人工数据可表达真实标准但昂贵且存在标注差异；蒸馏数据便宜、规模大、格式稳定，但会继承教师错误、偏见和能力上限。

## [[../08-后训练与对齐/03-人类反馈强化学习|03-RLHF]]

1. 人类偏好不是可直接对每个新回答求导的函数；奖励模型把偏好样本拟合成可重复打分的近似奖励，供策略优化使用。
2. 奖励 hacking 是策略找到提高代理奖励却违背真实目标的捷径。例如奖励偏爱长回答，模型便重复废话来得高分。
3. KL 惩罚限制新策略偏离参考模型过远，减少语言崩坏和对奖励模型漏洞的过度利用；系数过大又会限制学习。
4. RLHF 的偏好来自人类；RLAIF 由另一模型按规则或标准提供反馈。后者更易扩展，但继承评审模型偏差。

## [[../08-后训练与对齐/04-直接偏好优化|04-DPO]]

1. DPO 从偏好概率模型推导出直接比较优选/劣选回答相对参考策略的目标，不先训练显式标量奖励模型，也不做传统在线 RL rollout。
2. $\beta$ 控制相对参考模型的偏离尺度及偏好差异的敏感度；具体效果依实现和数据，需调参验证。
3. 两者都使用偏好数据；DPO 显式比较策略相对参考模型的对数概率，ORPO 把监督似然与偏好 odds 目标结合并可不使用单独参考模型。
4. DPO 通常先依靠 SFT 建立基本指令行为，再用偏好对调整相对概率；ORPO 的目标包含 SFT 负对数似然和偏好 odds 项，可以在同一阶段同时学习示范回答与偏好排序，因此不要求预先独立完成 SFT。

## [[../08-后训练与对齐/05-组相对策略优化|05-GRPO]]

1. PPO 常训练价值函数估计优势并限制策略更新；GRPO 对同一提示采样一组回答，用组内奖励相对值形成优势，可省去单独价值模型。具体实现仍可能包含裁剪和 KL 项。
2. 有可自动检查结果的任务，如有唯一可核算答案的数学题、能运行测试的代码题、规则可验证的格式任务。
3. 同组回答共享问题难度基线，减去组均值后比较相对好坏，可降低跨题奖励尺度差异；“更稳定”仍取决于奖励噪声和采样。
4. 均值和方差估计噪声大，回答可能缺少好坏差异；极端时全组奖励相同，学习信号接近 0。

## [[../08-后训练与对齐/06-合成数据与蒸馏|06-合成数据与蒸馏]]

1. 生成器错误会被批量复制；筛选器若也依赖相似模型，可能无法发现同类错误，导致反馈循环。
2. 输出蒸馏学习答案或概率；理由蒸馏还学习中间解释步骤，信息更丰富，但错误理由也更容易传递。
3. 软概率展示了非正确类别间的相对关系，提供“哪些答案接近”的信息；只用硬标签会丢掉这些教师信号。
4. 建立人工核验的分层样本；检查正确性、重复、泄漏、毒性和来源；训练前后在独立真实测试集比较，并抽查模型是否复现教师错误。

## [[../08-后训练与对齐/07-推理训练|07-推理训练]]

1. 不建议把未验证的自由文本“思维链”当唯一标准。可示范可核验步骤：题目 `23+19`；步骤 `23+10=33，33+9=42`；答案 `42`。
2. 过程奖励能在中途提供密集反馈但步骤标注昂贵且可能奖励固定写法；最终奖励客观易验但稀疏，无法指出错误发生在哪里。
3. 中间文字可能包含抵消的错误、事后拼接解释，或最终答案由其他内部计算路径得到；可见理由不保证忠实反映内部机制。
4. 普通 SFT 模仿给定答案；推理训练通常强调多步任务、过程/结果验证、采样比较或强化信号。二者边界取决于具体数据和目标。

## [[../08-后训练与对齐/08-LoRA 与参数高效微调|08-LoRA]]

1. $r(d_{in}+d_{out})=16(1024+1024)=32,768$ 个参数；全矩阵为 $1,048,576$，约占 3.125%。
2. 更新写成 $BA$，其秩最多为 $r$，当 $r$ 远小于输入输出维度时是低秩更新。
3. QLoRA 通常把冻结的基础模型权重量化存储与计算，同时训练 LoRA 适配器；不是直接训练量化后的全部基础权重。
4. LoRA 适合资源有限、多任务分别保存适配器和希望保留基础模型时；全量微调适合有充足资源、需大幅改变模型且能承担存储和遗忘风险时。最终应由任务评测决定。

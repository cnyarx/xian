# 词表与编码

## 词表

词表（Vocabulary）是 tokenizer 能使用的全部 token 与整数 ID 的对应表：

```text
0  → <pad>
1  → <bos>
2  → <eos>
3  → 我
4  → 喜欢
5  → 人工
6  → 智能
...
```

词表大小记为 $V$。常见模型词表从数万到二十多万不等；具体数字必须查对应模型配置。

## 编码与解码

**编码（Encoding）**：文本 → token → ID。

```text
"我喜欢人工智能"
→ ["我", "喜欢", "人工", "智能"]
→ [3, 4, 5, 6]
```

**解码（Decoding）**：ID → token → 文本。

```text
[3, 4, 5, 6]
→ ["我", "喜欢", "人工", "智能"]
→ "我喜欢人工智能"
```

Tokenizer 负责在人类文本与 token ID 之间翻译。语言模型前向计算接收 token ID，输出每个位置对词表的 logits（未归一化分数）；生成算法根据 logits 选择下一个 token ID，最后再由 tokenizer 解码成文本。

```text
文本 → tokenizer 编码 → 输入 ID → 模型 logits → 采样/搜索 → 输出 ID → tokenizer 解码 → 文本
```

## 特殊 token

- `<bos>`：Beginning of Sequence，序列开始。
- `<eos>`：End of Sequence，序列结束；生成到它通常停止。
- `<pad>`：Padding，把不同长度序列补齐后组成批次。
- `<unk>`：Unknown，无法表示的内容；字节级 tokenizer 通常可避免。
- 对话模型还可能有 system、user、assistant 边界 token。

特殊 token 的名字和 ID 由具体 tokenizer 定义，不能假定所有模型一致。

## 注意力掩码

补齐 token 不应影响模型计算。注意力掩码（Attention Mask）标记真实 token 与 padding：

```text
IDs:   [3, 4, 6, 2, 0, 0]
Mask:  [1, 1, 1, 1, 0, 0]
```

## 词表大小的取舍

大词表：

- 文本通常被切得更短。
- 嵌入和输出层参数更多。
- 低频 token 可能训练不充分。

小词表：

- 参数较少。
- 序列更长，注意力计算更贵。
- 单位更通用。

## 一个参数量例子

若词表 $V=100000$，隐藏维度 $d=4096$：

$$V\times d=100000\times4096=409,600,000$$

仅嵌入矩阵就约 4.096 亿参数。若输入输出权重共享，可避免再增加一份同规模参数。

## 常见误区

- token ID 大小不表示词的重要性。
- 解码不一定完全按肉眼想象分隔，空格可能属于相邻 token。
- 聊天模板也是编码流程的一部分；模板错误会显著影响模型行为。

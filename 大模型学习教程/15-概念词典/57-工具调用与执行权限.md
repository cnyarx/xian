# 工具调用与执行权限

## 一句话定义

工具调用（Function Calling / Tool Use）让模型按约定格式提出工具名称和参数，由外部程序执行并返回结果；关键安全原则是模型只提建议，执行和权限由系统控制。

## 直觉理解

模型像是能打电话的秘书，可以提议"查一下天气"，但秘书没有钥匙、不能划账。系统接到请求后在自己权限内执行，只把结果返回给秘书。

## 严格定义

模型输出结构化 JSON：

```json
{"name":"search_weather","arguments":{"city":"杭州"}}
```

系统验证格式、参数类型和权限后才执行。执行结果作为下一条上下文消息返回模型。

## 例子

用户问"北京今天几度"，模型提出 `weather_query(city="北京")`，系统调用 API 获取温度，返回 JSON，模型据此生成最终回答。

## 边界

- 工具调用本身不执行代码，需要外部程序；
- 模型输出可能被恶意构造，参数必须验证；
- 工具应有最小权限和速率限制；
- 不可信输入绝不应获得工具调用权限。

## 最小自测

1. 工具调用和普通文本生成有什么区别？
2. 为什么工具参数必须验证？

答案：1. 工具调用产生结构化数据而非自由文本，用于触发外部操作；2. 模型可能输出超出预期的参数，如 SQL 注入或路径遍历。

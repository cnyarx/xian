# 推理阶段与延迟指标

## 一句话定义

大模型推理分为 Prefill（处理整个输入并建立 KV Cache）和 Decode（逐 token 生成输出）两个阶段；TTFT 衡量首 token 延迟，TPOT 衡量后续每个 token 的平均延迟，吞吐量衡量单位时间完成的 token 或请求数。

## 直觉理解

Prefill 像读完一整本问题，Decode 像一个字一个字写答案。长问题主要影响 TTFT，长回答主要影响总延迟和 TPOT。

## 严格定义

- TTFT = 请求到达至首个输出 token 的时间；
- TPOT = 生成阶段全部解码时间 / (输出 token 数 − 1)——即首 token 之后平均每个 token 的生成时间；
- 吞吐量 = 单位时间处理的 token 或请求数；
- 端到端延迟 = TTFT + (输出 token 数 − 1) × TPOT（近似）。

## 例子

TTFT=500ms，TPOT=50ms，生成 100 个 token，总延迟约 $0.5+99×0.05=5.45$ 秒。

## 边界

- 只有 1 个输出 token 时没有“首 token 之后”的间隔，TPOT 不适用；
- 有些系统把 ITL（Inter-Token Latency）逐间隔统计，再取均值或分位数；报告性能时必须写明口径；
- 不同系统对 token 计数口径可能不同；
- 批处理提高吞吐量但可能增加单请求延迟；
- 流式输出改善感知延迟，不减少总计算量；
- P99 尾延迟比平均延迟更能反映用户体验。

## 最小自测

1. 输入很长主要影响哪个指标？
2. 输出很长主要影响哪个指标？

答案：1. TTFT；2. TPOT 和总延迟。

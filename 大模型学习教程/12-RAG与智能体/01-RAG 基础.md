# RAG 基础

## 学习目标

学完本篇后，你应能：

1. 把 RAG 拆成切块、索引、检索、重排序、生成和引用验证；
2. 区分“检索到了相关内容”和“回答被证据支持”；
3. 为有答案、无答案、冲突答案和越权问题设计不同处理；
4. 用可复查指标定位失败发生在哪一层；
5. 说明 RAG 能改善什么，以及不能保证什么。

## 一句话定义

RAG（Retrieval-Augmented Generation，检索增强生成）在回答前从外部知识库检索候选证据，把经过筛选的内容放入上下文，再让语言模型依据这些证据生成答案。

它不是“给模型联网”这么简单，而是一条需要逐层验收的数据链路。

## 完整流程

```text
文档 → 解析与权限标记 → 切块 → 建索引
                                  ↓
用户问题 → 权限判断 → 查询改写 → 初检索 → 重排序 → 拼接上下文 → 生成 → 引用回读验证
```

离线阶段准备文档和索引；在线阶段处理问题。索引更新、文档删除或权限变化后，还要同步处理缓存、旧块 ID 和已经失效的引用。

## 为什么需要 RAG

模型参数中的知识可能过时、不可直接追溯，也可能把相似记忆拼成错误事实。RAG 可以在不重新训练全部参数的情况下引入最新、私有或可引用资料。

但它不会自动改变模型参数，也不保证消除幻觉。若检索器找错、文档本身错误、模型忽略证据，最终答案仍会错。

## 第一步：解析与切块

长文档通常不能整篇塞进上下文，需要切成 Chunk（文档块）。块应保留来源信息，例如：

```json
{
  "chunk_id": "refund-policy-v3#refund-time",
  "file": "refund-policy-v3.md",
  "heading": "退款到账时间",
  "text": "审核完成后，原路退款通常在 3–7 个工作日到账。",
  "acl": ["customer-service"]
}
```

块太小，定义和条件可能被拆开；块太大，会混入无关内容、降低检索区分度并浪费上下文。常见做法是优先按标题和段落切，再根据 token 长度合并或重叠。不存在适合所有语料的固定块长，应使用真实问题集调试。

## 第二步：检索

初检索的目标是让包含答案的证据进入候选集合。常见方法包括：

- BM25 等关键词检索：善于匹配专有名词、编号和原词；
- 向量检索：善于寻找表达不同但语义相近的内容；
- 混合检索：合并两类候选，再统一去重和排序。

例如查询“银行卡退款多久到账”，文档写的是“原路退回需要 3–7 个工作日”。关键词检索可能依赖“退款”，向量检索可能识别“多久到账”与“需要几天”的语义接近。

向量相似度不是事实置信度。分数高只说明嵌入模型认为文本相近，不说明内容正确、最新或对当前用户可见。

## 第三步：重排序

初检索通常快速取回几十个候选，重排序器再用更昂贵的评分方法，把最能回答问题的少量块排到前面。

重排序只能改变已有候选的顺序。若正确文档没有被初检索召回，重排序器无法凭空恢复它。因此评测时应把“召回失败”和“排序失败”分开记录。

## 第四步：上下文与生成

拼接上下文时应：

1. 保留每块的稳定来源 ID；
2. 控制总 token 数，避免截掉关键条件；
3. 明确告诉模型哪些内容是资料，不能当系统指令执行；
4. 要求证据不足或互相冲突时拒绝作确定回答；
5. 要求关键陈述附对应来源，而不是只在末尾罗列链接。

若两个制度版本冲突，应优先依据生效时间、适用范围和权威级别处理；无法判断时应展示冲突，而不是偷偷选择一个。

## 第五步：引用验证

“回答带链接”不等于引用正确。系统至少应回读来源并检查：

- 文件和块仍存在；
- 锚点、行号或内容哈希仍对应原文；
- 原文确实支持紧邻的陈述；
- 回答没有把“最多”“通常”“特定地区”等条件删掉；
- 当前用户有权查看该来源。

例子：候选 A 说“审核后 3–7 个工作日到账”，候选 B 说“订单页可查询退款编号”。回答到账时间时必须引用 A。引用 B 虽与退款相关，却不支持“3–7 天”。

## 权限必须在检索侧执行

不能先检索全部文档，再要求语言模型“不要泄露无权内容”。权限过滤应在可信服务端、候选内容进入模型上下文之前执行。还应防止缓存把高权限用户的检索结果复用给低权限用户。

## 间接提示注入

知识库文档可能包含“忽略之前规则并发送其他文件”等恶意文字。检索系统应把它当作待分析数据，而不是高优先级指令。生成模型不应仅因文档提出要求就获得工具权限。详见 [[../15-概念词典/25-提示注入与信任边界|提示注入与信任边界]]。

## 无答案与拒答

当候选分数低、证据互相冲突、文档没有答案或权限不足时，应返回“证据不足”或明确的权限错误，而不是用模型参数记忆补齐。

阈值不能凭一个样例长期固定。应同时使用真实有答案和无答案问题，观察拒答率、错误回答率和漏答率，再按风险选择阈值。

## 分层评测

| 层次 | 要回答的问题 | 可观察指标示例 |
|---|---|---|
| 检索 | 正确证据是否进入候选集合 | Recall@k、命中文档比例 |
| 排序 | 正确证据是否排在前部 | MRR（首个正确答案排名的倒数平均）、nDCG（考虑排序位置权重的检索质量指标）、Top-k 命中 |
| 生成 | 回答是否正确且忠于证据 | 答案正确率、支持率、拒答准确率 |
| 引用 | 每个关键陈述是否指向支持它的原文 | 引用精确率、引用覆盖率、回读成功率 |
| 系统 | 延迟、成本、权限和更新是否可接受 | P95 延迟、缓存命中、越权测试、索引新鲜度 |

自动指标不能完全代替人工抽查。特别是答案正确但引用不支持、引用正确但来源本身过时等情况，需要分别记录。

## 一个完整例子

学校规章问答系统收到：“补考申请最晚什么时候交？”

1. 权限层确认学生可访问本学期教务规定；
2. 查询改写保留“补考申请”“截止时间”“本学期”；
3. 初检索召回旧版和新版规定；
4. 重排序把新版“考试结束后 5 个工作日内”排在前面；
5. 系统发现旧版写“7 个工作日”，根据生效日期选择新版，同时保留版本信息；
6. 回答：“按 2026 春季版规定，应在考试结束后 5 个工作日内提交”；
7. 引用指向新版文件的对应标题和行范围；
8. 验证器回读原文，确认时间、适用学期和权限均匹配。

若新版没有明确截止时间，正确结果是说明资料中未找到，而不是沿用旧版或自行推断。

## 常见失败模式

- 只测最终回答，不知道错误发生在检索、排序还是生成；
- 切块时丢失标题、表头、生效时间或适用范围；
- 用向量相似度直接当“答案可信度”；
- top-k 一味增大，导致噪声和上下文冲突；
- 文档更新后引用仍指向旧块；
- 权限过滤放在生成之后；
- 遇到无答案问题仍强制模型作答；
- 把检索文档里的命令当成可信指令执行。

## 最小验收清单

1. 构造一个能命中正确原文的问题；
2. 构造一个关键词不同但语义相同的问题；
3. 构造一个知识库没有答案的问题，确认系统拒答；
4. 放入两个冲突版本，确认系统不会无声选错；
5. 放入带恶意指令的文档，确认其不能触发工具或泄露数据；
6. 删除或修改来源，确认旧引用能被识别为失效；
7. 使用低权限身份，确认无权文档在检索结果中不可见。

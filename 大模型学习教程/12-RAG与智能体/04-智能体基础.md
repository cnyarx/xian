# 智能体基础

## 一句话定义

大模型智能体（LLM Agent）是“模型 + 工具 + 状态 + 控制循环”的软件系统。模型提出下一步行动，程序负责权限、执行、记录和终止。模型不是操作系统，也不应凭一段自然语言直接获得全部权限。

先读：[[../15-概念词典/23-智能体状态与控制循环|智能体状态与控制循环]]。

## 1. 从普通问答到智能体

普通问答大致是：

```text
输入 → 模型 → 文本输出
```

智能体则反复运行：

```text
读取状态 → 选择行动 → 校验权限和参数 → 执行工具
→ 记录真实观察 → 更新状态 → 检查终止条件
```

只要模型输出“我要调用工具”，工具并不会自动执行。宿主程序必须解析结构、检查权限，并决定执行、拒绝或要求确认。

## 2. 状态模型

状态（State）是下一步决策需要的已保存信息，可包括：

```yaml
goal: 查明退款失败原因
facts:
  - payment_captured: true
tool_results:
  - refund_id: null
pending:
  - 查询支付网关错误
permissions:
  - order.read
step: 2
max_steps: 6
```

模型上下文是短期状态的一部分。数据库、文件和工作流引擎可保存长期状态。模型参数不会因一次对话自动写入用户记忆。

## 3. 一个完整执行案例

任务：调查订单 `A123` 的退款失败原因，但不执行退款。

### 第 1 步：建立约束

- 目标：找到可引用的失败原因；
- 权限：订单和支付日志只读；
- 终止：找到明确错误，或 6 步后停止；
- 禁止：创建退款、发消息、修改订单。

### 第 2 步：查询订单

工具真实返回：

```json
{"payment_captured": true, "refund_id": null}
```

状态只能记录这些事实，不能猜一个退款号。

### 第 3 步：查询网关日志

真实返回：

```json
{"code": "INVALID_CURRENCY", "expected": "USD", "received": "US"}
```

### 第 4 步：完成判断

智能体输出失败原因、证据和建议，不调用写工具。此时终止条件已满足。

这个流程的可靠性来自“每一步以工具结果修正状态”，不是来自模型一次生成很长的推理。

## 4. 规划

规划（Planning）把复杂目标拆成子目标。常见方式：

- 先规划后执行；
- 每步执行后重规划；
- 维护可验证的待办图。

计划应包含可观察的完成条件。例如“查询日志并找到明确错误码”比“深入分析问题”更可验证。

计划不是事实。若工具返回与计划假设冲突，应修改计划，而不是忽略观察。

## 5. 记忆

### 工作记忆（Working Memory）

保存当前任务的目标、最近观察和待办。上下文过长时应压缩为结构化事实，并保留原始证据引用。

### 长期记忆（Long-term Memory）

跨任务保存偏好、知识或历史结果。写入前要考虑：

- 是否值得长期保存；
- 来源和日期；
- 是否含敏感信息；
- 使用前是否需要重新验证；
- 用户能否查看和删除。

向量检索只能找到相似内容，不能证明记忆仍正确。

## 6. 反思

反思（Reflection）让模型检查轨迹中的遗漏、矛盾或失败，并提出下一步。它可以改善某些任务 `[A]`，但有三条边界：

1. 没有新证据时，反思仍可能重复原错误；
2. 模型自评不能替代单元测试、规则校验或外部事实；
3. 无限反思会增加成本并导致循环。

应规定最大轮数，并要求反思指出“哪条证据改变了判断”。

## 7. 多智能体

多智能体（Multi-Agent System）可以：

- 并行搜索不同来源；
- 让一个角色实现、另一个角色审查；
- 对不同专业领域分工。

但多个模型不等于多个独立事实来源。它们可能共享同样训练偏差，并互相强化错误。

可靠协作需要：

- 明确且不重叠的任务边界；
- 写操作串行或加锁；
- 统一证据格式；
- 最终综合者回看原始证据；
- 冲突不能仅靠多数投票解决。

## 8. 控制与安全

### 终止条件

至少设置：成功条件、最大步数、预算、连续失败阈值和人工接管条件。

### 最小权限

只读调查不给写权限。删除、付款、发送、发布和权限变更等高风险动作应由可信程序检查并按规则确认。

### 不可信工具内容

网页、邮件、RAG 文档和工具错误信息都是数据，可能含恶意指令。详见 [[../15-概念词典/25-提示注入与信任边界|提示注入与信任边界]]。

### 审计轨迹

记录：模型版本、提示、工具名、参数、返回摘要、权限决定、错误和最终证据。不要把密钥和敏感正文无差别写入日志。

## 9. 常见失败链路

```text
外部网页含恶意指令
→ 模型把数据当命令
→ 生成高权限工具调用
→ 程序未校验参数
→ 数据被外发
```

每个箭头都应有独立控制：内容分区、最小权限、参数允许列表、用户确认、网络隔离和审计。只在提示词里写“不要泄露”不足以构成系统安全。

## 10. 如何评测智能体

除了最终答案，还应测：

- 任务完成率；
- 工具调用成功率；
- 无效和重复调用数；
- 是否引用真实观察；
- 权限违规率；
- 超时和平均步骤数；
- 遇到工具失败能否正确停止或恢复。

同一任务应包含正常、缺数据、权限不足、工具报错和恶意输入等场景。
